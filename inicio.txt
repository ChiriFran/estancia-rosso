quiero generar# Proyecto: Estancia Rosso — E-commerce (San Isidro, Buenos Aires)

Inicializá un proyecto nuevo de e-commerce desde cero, replicando exactamente el stack y la arquitectura del proyecto "mixing-nuts" (D:\proyectos\mixing-nuts). Usalo como referencia para copiar estructura, patrones y configuración. El nuevo proyecto se llama **estancia-rosso** y va en `D:\proyectos\estancia-rosso`.

## Datos del negocio
- **Nombre:** Estancia Rosso
- **Ubicación:** San Isidro, Buenos Aires, Argentina
- **Moneda:** ARS (pesos argentinos)
- **Idioma:** es-AR
- **Rubro:** A definir por el usuario (mantené la arquitectura genérica de e-commerce)

## Stack tecnológico (idéntico a mixing-nuts)
- **Frontend:** React 19 + Vite 8 (JavaScript puro, sin TypeScript)
- **Routing:** react-router-dom v7
- **Estado global:** React Context (CartContext)
- **Backend/DB:** Firebase (Firestore + Storage + Auth)
- **Scripts admin:** firebase-admin (seed de productos)
- **Lint:** Oxlint con plugin react
- **Estilos:** CSS puro por componente (.css junto a cada .css), más globals.css y variables.css
- **Deploy:** Vercel con SPA rewrites
- **Extras:** xlsx (import de productos por Excel), sharp (optimización de imágenes), WhatsApp util

firestore.rules
Copiar exactamente el contenido de D:\proyectos\mixing-nuts\firestore.rules y reemplazar el UID de admin (WB00Y17z2mYEGm6iofyAVX1Gh863) por el nuevo VITE_ADMIN_UID. Las colecciones son: productos, categorias, ordenes. Validaciones: órdenes solo con transferencia/efectivo, stock solo puede bajar con ultimaReservaId, solo admin crea/edita/borra.
storage.rules
Copiar de D:\proyectos\mixing-nuts\storage.rules y reemplazar el UID admin. Ruta de imágenes: images/products/{fileName}, máx 5MB, solo image/*.
Modelo de datos (Firestore)
- productos: id, nombre, slug, descripcion, precio, stock, imagenes[], categoriaId, activo, destacado, ultimaReservaId
- categorias: id, nombre, slug, imagen, activo
- ordenes: id, cliente{nombre, apellido, telefono, email}, entrega{tipo: envio|retiro, direccion, localidad}, productos[], subtotal, total, metodoPago: transferencia|efectivo, estado: pendiente|confirmada|enviada|entregada|cancelada, createdAt (ISO string)
Rutas de la app
- / → Home (hero slider, productos destacados, categorías, CTA contacto)
- /productos → listado con búsqueda y filtro por categoría
- /producto/:slug → detalle de producto
- /carrito → carrito de compras
- /checkout → formulario de checkout (cliente + entrega + método de pago)
- /pedido-confirmado → confirmación de orden
- /nosotros → About
- /admin → panel admin (protegido por AdminRoute + login Firebase Auth)
- CRUD productos (con import Excel vía xlsx)
- Gestión de clientes/órdenes
- Cambio de estado de órdenes
Firebase services (src/services/)
- firebase.js → initializeApp con env vars VITE_FIREBASE_*, exporta auth, db, storage
- products.js → CRUD productos en Firestore
- orders.js → crear órdenes, consultar por admin
- categories.js → CRUD categorías
- scripts/firebaseAdmin.js → cliente firebase-admin para seed (usa FIREBASE_CLIENT_EMAIL y FIREBASE_PRIVATE_KEY)

Notas importantes
- NO usar TypeScript, todo en JavaScript (.jsx)
- NO usar librerías de UI externas (sin Tailwind, MUI, etc.) — CSS puro
- Cada componente tiene su .css propio junto al .jsx
- Firebase config se lee de import.meta.env.VITE_*
- El seed se ejecuta con npm run seed y requiere .env con credenciales firebase-admin
- Las imágenes de productos se suben a Firebase Storage en images/products/
- Mantener la validación estricta de Firestore rules (solo admin edita, stock solo baja con reserva)
- El checkout valida stock antes de crear la orden y descuenta stock en la misma transacción
